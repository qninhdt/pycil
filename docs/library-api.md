# Library UI read contract

## Deck details

`GET /v1/library/nodes/{id}` returns node metadata, safe breadcrumbs, total
`sense_count`, and for a DECK the first bounded `sense_page`. Folder/reference
metadata does not automatically expand every descendant Sense.

`GET /v1/library/nodes/{id}/senses?after_id=...` returns the same page shape for a
deck, folder scope or live reference. `after_id` is the last Sense integer ID, not
an offset or UUID. Membership is unordered; pagination orders by Sense ID.

```json
{
  "senses": [{
    "sense_id": 1,
    "word_id": 1,
    "lemma": "bank",
    "entry_type": "WORD",
    "pos": "NOUN",
    "tier": "CORE",
    "definition": "a financial institution",
    "cefr_level": "B1",
    "register": null,
    "ipa_uk": "/bæŋk/",
    "ipa_us": null,
    "learning": {
      "state": "DUE",
      "mastery": 50,
      "due_at": "2026-10-02T00:00:00Z",
      "last_rating": "GOOD"
    }
  }],
  "next_after_id": 1
}
```

`next_after_id` is null for the final page. Neutral saved definitions are used;
missing fields remain null rather than inventing content. State is `NEW`, `DUE`
or `NOT_YET_DUE`, assessed at read time. New mastery is 0; learned mastery is the
configured stability projection, not a fluency score. `learning` is null for an
anonymous viewer and otherwise always belongs to the viewer, never the deck owner.

These fields let the UI render a Sense row, distinguish multiple senses of a word,
show pronunciation/level/progress, open `/v1/words/{word_id}` for full lexical
details, and send the correct integer `sense_id` for membership or learning.
Examples, forms, patterns, collocations, relations and Question pools are omitted
from this list payload. Preparation remains its own learning operation.

## Query and privacy guarantees

- Authorization uses the same live public/inherited/reference rules as study/tools.
  A revoked/private/deleted target returns 404, not empty data or leaked content.
- For an authorized deck, membership uses the `(deck_id, sense_id)` primary key
  directly; there is no recursive whole-library scope query for its page/count.
- The membership page is limited before joining public Lexi Word/Sense/Definition
  read mappings and the viewer's memory. One JOIN hydrates all displayed rows;
  no per-Sense API call or Question/example loading occurs.
- Page size is configured in YAML. The endpoint executes 3 fixed queries including
  authorization, regardless of how many Senses are displayed.
- Membership `position` and its unique index are removed in migration
  `0002_deck_membership`. Existing IDs/memberships/FKs remain intact. UUIDv7 applies
  only to IDs newly generated by Pycil, not Lexi integer identities or client keys.
